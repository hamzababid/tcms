## 1. Overview

- REST resources; non-CRUD operations are explicit action endpoints (`POST /…/approve`).
- Items are addressed by UUID. Project-scoped collections are nested under `/projects/{project_id}`.
- Every response for a mutable resource includes `row_version`.
- The frontend uses only this API (no private endpoints), so anything the UI can do, an API token can do (within scope and permissions).

## 2. Conventions

### 2.1 Authentication

| Mode | How | CSRF |
| --- | --- | --- |
| Browser session | Cookie `tcms_session` (HttpOnly, Secure, SameSite=Lax) | Required on POST/PUT/PATCH/DELETE: header `X-CSRF-Token` = value of cookie `tcms_csrf` |
| API token | `Authorization: Bearer tcms_<40 chars>` | Not required; cookies ignored |

Unauthenticated → `401 unauthenticated`. Expired session → `401 session_expired`. Second factor pending (enrolled, not yet verified) → `401 mfa_required`. MFA enrolment pending → `403 mfa_enrollment_required` except `GET /auth/me`, `POST /auth/logout`, `POST /auth/mfa/setup`, `POST /auth/mfa/enable`. Cookie-authenticated writes without a matching `X-CSRF-Token` → `403 csrf_failed`. Unauthenticated POSTs (login, MFA verify, forgot/reset, invitation accept) reject a foreign `Origin` header (`403 csrf_failed`). API tokens with scope `read` get `403 token_scope_insufficient` on any write.

### 2.2 Authorization

- Each endpoint lists its permission. Org Admins pass every project permission.
- Project resources for which the caller is not a member return `404 not_found` (no existence leak). Members lacking the permission get `403 permission_denied` with `required_permission`.

### 2.3 Data formats

| Kind | Format |
| --- | --- |
| IDs | UUID string |
| Timestamps | ISO 8601 UTC with `Z` (`2026-11-03T10:15:00Z`) |
| Dates | `YYYY-MM-DD` |
| Enums | lower_snake strings (see [05 §2](05-Database-Design.md)) |
| Markdown | string |
| Users in responses | `{"id","display_name","email","is_active"}` (`UserRef`) |
| Entity refs | `{"id","key","title"}` (`EntityRef`) |

### 2.4 Pagination

Request: `?page=1&page_size=50` (max 200). Response envelope:

```json
{ "items": [ ... ], "page": 1, "page_size": 50, "total": 1342 }
```

Exports and job-based lists never paginate beyond 200 per page; use export endpoints for bulk data.

### 2.5 Sorting

`?sort=-updated_at,key` — comma-separated, `-` for descending, max 3 fields; allowed fields documented per endpoint; unknown field → `400 invalid_sort`.

### 2.6 Filtering

- Simple equality: `?status=failed`; multiple values: `?status=failed,blocked` (OR).
- Operators via suffix: `field__ne`, `field__in`, `field__gte`, `field__lte`, `field__contains`, `field__isnull=true`.
- Free text: `?q=login` (searches title/key and, where supported, full text).
- Unknown filter fields → `400 invalid_filter`. Filters are allow-listed per endpoint.

### 2.7 Concurrency

- Updates include `row_version` in the body **or** `If-Match: "<row_version>"`. Missing → `428 row_version_required`; stale → `409 stale_row_version` with `current` (the latest representation) in the problem body.
- Responses carry `ETag: "<row_version>"` for single resources.

### 2.8 Idempotency

`Idempotency-Key: <uuid>` accepted on all POST creates; replay within 24 h returns the original response (`Idempotency-Replayed: true`). Same key with a different body → `422 idempotency_key_reused`.

### 2.9 Includes

Detail endpoints accept `?include=` for expensive sub-resources (e.g. `GET /runs/{id}?include=version,draft,history`). Unknown include → `400`.

### 2.10 Rate limits

Auth endpoints: 20/min/IP. General: 600/min/user. Responses include `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`; exceeded → `429 rate_limited` with `Retry-After`.

### 2.11 Versioning and compatibility

- Additive changes (new fields, endpoints, enum values) are non-breaking; clients must ignore unknown fields and tolerate unknown enum values (display raw).
- Breaking changes → `/api/v2`; v1 supported ≥ 6 months after v2 release; `Deprecation` and `Sunset` headers on deprecated endpoints.

## 3. Errors

```json
{
  "type": "https://tcms.example.com/problems/incomplete_attempt",
  "title": "Attempt cannot be finalized",
  "status": 422,
  "code": "incomplete_attempt",
  "detail": "Steps 4 and 5 have no result. Record them or choose Blocked, Skipped or Not applicable with a reason.",
  "instance": "/api/v1/results/0193…/finalize",
  "request_id": "req_7f3c…",
  "errors": [ { "field": "steps[3].status", "code": "not_recorded", "message": "Step 4 has no result" } ]
}
```

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `bad_request`, `invalid_filter`, `invalid_sort`, `invalid_include` | Malformed request |
| 401 | `unauthenticated`, `session_expired`, `invalid_credentials`, `mfa_required`, `invalid_mfa_code` | Authentication |
| 403 | `csrf_failed` | Missing/invalid CSRF token or foreign Origin |
| 403 | `permission_denied`, `mfa_enrollment_required`, `self_approval_not_allowed`, `transition_not_permitted`, `not_assignee`, `token_scope_insufficient`, `not_author`, `edit_window_closed` (comments) | Authorization |
| 404 | `not_found` | Missing or not visible |
| 409 | `conflict`, `already_linked`, `stale_row_version`, `project_key_taken`, `name_taken`, `project_archived`, `cycle_closed`, `draft_exists`, `run_has_results`, `run_superseded`, `already_latest`, `invalid_status`, `folder_not_empty`, `immutable_record`, `case_has_runs`, `case_archived`, `automation_key_taken`, `folder_archived`, `link_limit`, `attachment_limit`, `system_tag`, `tag_in_use`, `last_org_admin`, `last_qa_manager`, `already_member`, `user_exists`, `mfa_already_enabled`, `mfa_required_by_policy`, `cannot_deactivate_self` | State conflict |
| 413 | `file_too_large` | Upload limit |
| 415 | `unsupported_file_type` | Upload type |
| 422 | `validation_error`, `rule_violation`, `incomplete_attempt`, `outcome_required`, `outcome_conflicts_with_steps`, `actual_result_required`, `reason_required`, `bug_link_required`, `folder_cycle`, `folder_too_deep`, `field_required`, `invalid_transition`, `idempotency_key_reused`, `no_eligible_version`, `token_invalid` (reset/invitation link unknown, used or expired), `password_policy`, `confirmation_mismatch` | Business rule |
| 423 | `account_locked` | Lockout (returned only after valid password, see [02 §3.3](02-Functional-Specification.md)) |
| 428 | `row_version_required` | Concurrency |
| 429 | `rate_limited` | Rate limit |
| 500 | `internal_error` | Bug (logged with request_id) |
| 503 | `unavailable` | Dependency down |

`validation_error` (Pydantic) uses `errors[]` with JSON-pointer-like `field` paths.

Comment and attachment notes (M2):

- **Mentions** are written in the body as `@[Display Name](user:<user uuid>)`. The server stores the mentioned user IDs (`mentions[]`), keeps only current project members, and notifies them (`comment.mentioned`). Clients render the token as the name.
- `entity_type` for comments: `test_case`, `test_case_version` (more types arrive with their milestones). Deleted comments stay in the list with `body: null, deleted: true`. `editable_until` = `created_at` + 15 min.
- Review comments from submit/approve/return are recorded on the **case** (AC-TD-22); the audit event names the version.
- `entity_type` for attachments: `test_case`, `test_case_step`, `test_step_result` (evidence on a step of a draft attempt: executor or `cycle.manage`; `409 immutable_record` once the attempt is final); bug links carry no attachments (ADR-023), evidence stays on the step. The size limit is the project's `attachment_max_mb` (≤ the org cap); the content type is sniffed from the bytes. `/content` serves images and PDFs `inline` and everything else as `attachment` (`?download=true` forces a download), always with `Content-Security-Policy: sandbox` and `X-Content-Type-Options: nosniff`. Removing a step attachment of an approved version returns `409 immutable_record` (BR-28).

## 6. Example flow — execute a run

```
GET  /api/v1/me/work                                         → cycles with my runs
GET  /api/v1/cycles/{cid}/runs?assignee_id=me&status=not_run,in_progress&sort=position&page_size=200
GET  /api/v1/runs/{rid}?include=version,draft,history,queue
POST /api/v1/runs/{rid}/results                               → 201 draft (attempt_no 1)
PATCH /api/v1/results/{res}/steps/{s1}  {"status":"passed"}
PATCH /api/v1/results/{res}/steps/{s2}  {"status":"failed","actual_result":"Took 9 s"}
POST /api/v1/attachments (multipart, entity_type=test_step_result, entity_id={s2 result id})

POST /api/v1/results/{res}/bug-links  {"reference":"SPK-431","step_id":"{s2}"}
POST /api/v1/results/{res}/finalize  {}                       → 200 status=failed
```
